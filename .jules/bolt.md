2024-08-21 - Probatum::collect Iterator Optimisation

Learning: The original `Probatum::collect` loop used a single `for item in iter` with an `Option<ErrorBuf>` to track whether we're in "error mode". This meant every `Valid` item paid the cost of an `if errors.is_none()` branch, which gets expensive over large collections. Since we only need to return valid values if *all* items are valid, encountering a single error means we can discard the collected values immediately.
Action: Used loop unswitching for iterator-based sequence aggregations. We iterate using `while let Some(item) = iter.next()` to collect values. Upon hitting the first error, we drop the values array and transition to a secondary `for item in iter` loop that solely accumulates subsequent errors. This avoids the `is_none` branch in the hot valid-collection path and reclaims memory eagerly when an error occurs, reducing overhead without breaking sequence error-accumulation semantics. Important: `iter.by_ref()` borrows `iter` for the lifetime of the outer loop body and prevents using `iter` in the inner loop; `while let Some(...) = iter.next()` immediately releases the borrow, allowing the inner loop to cleanly consume `iter`.
